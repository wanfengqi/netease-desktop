## 二、三个必须先知道的坑（都已修复并留下说明）

### 2.1 【致命】S0 骨架的 CSP 漏了 `media-src`，把所有音频拦死

- **现象**：点歌后 `audio.src` 写进去了，但立刻 `error.code = 4`，
  `networkState = 3`（NETWORK_NO_SOURCE），控制台消息是
  `MEDIA_ELEMENT_ERROR: Media load rejected by URL safety check`。
- **排查**：先怀疑混合内容（页面 http 加载 http 音频）→ 换成 https 失败；
  再试 `data:` URI → 也失败。三者全挂说明不是网络/协议问题，而是策略层。
- **根因**：`app/index.html` 的 CSP 是
  `default-src 'self'; script-src ...; style-src ...; img-src ...; connect-src ...`
  —— **没有 `media-src`**，于是音频回落到 `default-src 'self'`，全部拒绝。
  旧版 `src/renderer/index.html` 一直有 `media-src 'self' data: https: http: blob:`。
- **修复**：在 `app/index.html` 补齐 `media-src`（并给 `img-src` 补 https/http、
  `connect-src` 补 `http://127.0.0.1:*`）。**`script-src` 没有放宽**，仍无 `unsafe-eval`。

> 这个坑对任何后续阶段都成立：只要 CSP 里没有 `media-src`，新壳永远无法出声。

### 2.2 【语义】`next()` 不能传 `keepHistory`

- 旧版 `next()` 调的是**裸** `playAt(i)`，会把当前曲压进历史栈；
  只有 `prev()` 回退时才传 `keepHistory: true` 避免乒乓。
- 我最初写成了 `playAt(target, { keepHistory: true })`，后果是
  "下一首 ×3 再上一首 ×3"无法原路退回（历史栈永远是空的）。
- 由新增测试 `player.history.test.ts` 捕获，已修正。

### 2.3 【环境】窗口被遮挡时 Chromium 会挂起媒体，表现为"点了歌但没声音"

- **现象**：端到端第一次通过之后，再跑就变成 `paused: true` 但 `duration=45, readyState=4`
  （音频**已加载**却不播放），且 `play()` 的 promise 被拒绝：
  ```
  AbortError: The play() request was interrupted because
  video-only background media was paused to save power.
  ```
- **根因**：调试期间用户在前台看视频，我们的窗口被遮挡 →
  `document.visibilityState === 'hidden'` → Chromium 判定为后台媒体并主动挂起。
- **为什么必须修（不是"调试环境才有的问题"）**：音乐播放器的基本要求就是
  **最小化 / 被遮挡时继续播放**。不修的话，用户切到浏览器看个网页音乐就停。
- **修复**（`electron/main.cjs`）：
  1. `app.commandLine.appendSwitch('disable-background-media-suspend')`
  2. `appendSwitch('disable-renderer-backgrounding')`
  3. `appendSwitch('disable-background-timer-throttling')`
  4. `webPreferences.backgroundThrottling: false`
  必须在上面的 `app.whenReady()` 之前调用，ready 之后设置不生效。
- **修复后实测**：`visibility: visible`，`play()` 正常 resolve，
  `paused: false`、`currentTime` 3 秒走 3.01 秒。

> 排查过程中的一条弯路值得记下：我给 `HTMLAudioElement` **实例**打 `src` 属性补丁时，
> 在原型上留下了一个不完整的描述符，导致 `engine.hasSource` 抛异常、播放静默失败。
> 结论：**诊断脚本不要改原型**，要用无副作用的方式（只读状态 / 拦截 `play`、`pause` 并回读事件）。
> 每次可疑测量前重启应用，避免补丁残留污染结论。

### 竞态修复的关键三行

```ts
const result = await this.resolver.resolve(song, { urlFor: fetcher });
if (!this.resolver.isCurrent(result.token)) {
  return { ok: false, stale: true, reason: '过期请求（已切歌）' };  // 静默丢弃
```

### 6.9 关于静音执行

被测机器当时正被用户用于看视频，因此本轮端到端**全程静音**：
Electron 启动参数 `--mute-audio`，且配置里 `muted=true`。
播放判定改用状态读数（`paused === false` + `currentTime` 按 1s/s 递增 + `readyState === 4`），
这是与"人耳确认"同等强度的证据 —— 若音频未真正解码播放，`currentTime` 不会推进。

**"听得见声音"这一项未做人耳确认**，原因是用户在用电脑；如需人耳复验，
请在用户空闲时打开应用，取消静音后点任意歌曲即可。

## 八、已知限制（如实记录）

1. **试听片段**：网易云大量热门曲目返回 45 秒试听（本篇"想你就写信"即 `duration=45`）。
   非 VIP 曲目如 "Try (Kung Fu Panda 3 Official Theme Song)" 实测 `duration=240.31` 完整可播。
   这不是 bug，是接口如实返回；UI 已用 VIP 角标标注。
2. **咪咕取址未在真实网络下标定**：S3 走的是同一套 `resolveSongUrl` 分支，但本轮实测的歌曲
   都来自网易云。咪咕分支由 `migu.repo.test.ts` 单测覆盖（含缺 copyrightId 抛错）。
3. **"听得到声音"未验证**：因用户在用电脑，全程静音。判定改用 `paused===false` +
   `currentTime` 递增 + `readyState===4`，这是同等强度的证据链；若需要人耳确认，
   请另行安排在用户空闲时执行。
4. **均衡器未接**：S2 遗留的 1.1（新旧字段并存）留到 S4；`defaultCrossOriginPolicy` 已是
   可注入的，接入时无需改 AudioEngine。
5. **收藏写操作未做**：`LibraryView` 只读展示 `favorites`，增删留 S4。
