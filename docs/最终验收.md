## 7. 本轮在打包版上才发现并修掉的缺陷

这三条 dev 阶段都没暴露，是「必须用 exe 验收」这条规矩的实际收益：

1. **迷你模式只能进不能出** —— Playbar 按钮不读回真实状态，退出后仍显示「迷你模式」。改为订阅 `win:exit-mini` 并用 `win.isMini()` 校准，按钮态与文案联动。
2. **三处重构期标记留在成品界面上** —— 按 `f642c25` 的真实 diff：
   - `app/index.html` 窗口标题 `网易云音乐 · 重构版` → `网易云音乐桌面版`；
   - `TitleBar.vue` 品牌位 `<em>重构版</em>` → 换成 `app/public/icon.png` 的 18px logo + 正式名称（原 `tb-dot` 状态点保留给主题当状态指示）；
   - `AppSidebar.vue` 页脚 `S3 · 播放链路` 阶段标记 → `v2.0.0`。
   exe 上实测侧栏页脚显示 `v2.0.0`，包内 HTML 标题已是正式名（`s9-asar-check.cjs` 的 `html_title_new` / `no_refactor_title` 两项断言）。
3. **歌曲行没有收藏入口（P0 功能缺口）** —— `LibraryView` 空态文案写着「在歌曲行上点收藏」，而 `SongRow` 模板里根本没有收藏键，搜索页右键菜单也没有收藏项，等于文案承诺了一条不存在的路。补了行内 ♡（hover 出现、已收藏常驻高亮，走 `favorites` store 直连，避免四个视图各抄一遍）+ 右键菜单收藏项 + heart/heartFilled 内联 SVG 图标（新增 `fillpath` 图元，实心/空心共用同一路径不跳形）。

## 9. 风险与兼容性

1. **`asarUnpack` 必须是 `node_modules/**/*`**。网易云 API 子进程是**普通 Node** 从 `app.asar.unpacked` 里 spawn 的，只解包它本体的话 axios 缺失 → 子进程退出 → 主进程卡在就绪等待 → 表现成「界面全卡、CDP 超时」，症状极具误导性（看着像渲染层崩了）。这条已固化成断言：`electron/services/__tests__/packaging.test.mjs`。
2. **重打包前必须先杀掉正在运行的打包 exe**，否则 `EPERM: unlink release\win-unpacked\dxcompiler.dll`。注意要杀的是**那个 exe 自己的后台 job**，不是构建 shell。
3. **electron-builder 偶发网络失败**：`Client network socket disconnected before secure TLS connection was established`，exit=1 且产物时间戳不变（＝没重建）。带 `ELECTRON_MIRROR` + `ELECTRON_BUILDER_BINARIES_MIRROR`（npmmirror）重试即通过。判据看 exe 的 mtime，别只看日志里出现过 packaging。
4. **配置目录**：新版写 `%APPDATA%\netease-desktop\next-config.json`，v1 的 `config.json` 只读迁移，不覆盖。要干净验收就用独立 `--user-data-dir`（本轮用的 `.s9-exe-userdata`，验完已删）。
5. **跨 IPC 的数据必须深转纯普通对象**：Vue 响应式代理不可结构化克隆，会抛 `An object could not be cloned.`；`extra.*` 里的自定义结构因此刻意存 JSON 字符串。
6. **旧版共存策略**：按用户决定「只留新版」，v1 源码进 git 归档，打包只出新版；回退靠备份目录而不是双版本并存。

```bash

  --remote-debugging-port=9415 \
  --user-data-dir="E:\\Huancun\\projects\\pv-mad\\netease-desktop\\.s9-exe-userdata" \

# 探针：CDP_MATCH 必给，否则迷你窗/桌面歌词窗开着时会选错页面

CDP_MATCH=桌面版 CDP_PORT=9415 node tools/cdp.js eval-file <probe.js>
CDP_MATCH=桌面版 CDP_PORT=9415 node tools/cdp.js shot docs/screenshots/xxx.png
```

探针写法的两条硬规矩（本轮踩过三次）：先断言当前视图与目标元素存在，再判功能缺失；
找不到目标要显式返回 `not_found`，不要回 `null` 让上层猜——「选择器落空」是探针的问题，不是应用的问题。
