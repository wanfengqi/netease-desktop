### 1.5 真实问题定位（这是重构的理由，不是文件大）

按 grep 实测，耦合集中在三处：

**问题 A：视图层直接操作播放器内部状态（views.js 引用 `Player.` 共 24 次）**
```
views.js:768   Player.audio.currentTime      ← 视图直接读播放内核的 <audio> 元素
views.js:849   Player.audio 相关
...
```
后果：任何让播放内核换实现（例如接 Web Audio 做缓存、做无间隙播放）的动作，都会连锁打断歌词页。

**问题 B：配置读写散落在两个模块共 16 处**
```
player.js:104  config.set({ playMode })
player.js:233  config.set({ queue... })
player.js:261  config.set({ recent })
player.js:276  config.set({ volume })
player.js:283  config.set({ muted })
player.js:377  config.set({ equalizer })
views.js:443   config.set({ favorites })
views.js:471   config.set({ favorites: [] })
views.js:488   config.set({ recent: [] })
views.js:557   config.set({ searchHistory })
views.js:627   config.set({ cookie })
views.js:651   config.set({ cookie: '' })
views.js:663   config.set({ cookie })
views.js:689   config.set({ cookie: '' })
views.js:739   config.set({ lyricOffset })
views.js:965   config.set({ source })
```
后果：加一个新设置项（本次要加的设置中心）需要改 3 个文件；且每次 set 都是全量写盘（`saveConfig` 每次 read+merge+write）。

**问题 C：无 service 层，页面各自拼接口参数**
存在统一入口 `app.js:66 api(path, params)`，但瘦身逻辑在主进程 `slimPayload`（main.js:254）按 path 字符串前缀硬匹配。新增任何接口都要去主进程加一个 if 分支。

### 1.6 三条会卡住重构的现成硬约束（不是风格偏好，是踩过坑写进项目准则的）

1. **渲染层是经典脚本全局作用域**，`const` 重名直接 SyntaxError → 上 ESM 必须同时改加载顺序与所有模块边界
2. **全屏浮层打开时必须关标题栏拖拽带**（`Views.syncOverlayClass()` 给 body 加 `overlay-open`），否则浮层顶部 38px 内按钮收不到任何鼠标事件（Electron 只对拖拽元素的后代做 no-drag 减法）
3. **跨歌身份一律用 `Norm.key(song) = source:id`**，音源字段映射只允许出现在 `normalize.js` 与 `migu.js`

### 1.7 基线健康度

11 个 JS 文件 `node --check` 全部通过；git 工作树除未跟踪的调试脚本（shots/_*.js）外干净，HEAD = `4dc3f72`。

## 三、目标架构

```
┌─────────────────────────────────────────────────────────┐
│ 主进程 (Electron main, ESM)                              │
│  ├─ windows/      主窗口 / 歌词窗 / 迷你窗                │
│  ├─ ipc/          按域拆分: window|theme|config|api|migu  │
│  ├─ services/     NeteaseApi 子进程 / MiguAdapter         │
│  └─ storage/      config / themes / 下载库 / 缓存索引      │
└────────────────────────┬────────────────────────────────┘
                         │ contextBridge (preload, 白名单)
┌────────────────────────┴────────────────────────────────┐
│ 渲染层 (Vue 3 + Vite + Pinia + TS)                       │
│  ├─ core/         audio engine · queue · playmode        │
│  ├─ data/         normalize (source:id) · repository     │
│  ├─ stores/       player · queue · config · download     │
│  ├─ components/   SongRow · SongList · Cover · ...       │
│  ├─ views/        Home Discover Search Playlist Album    │
│  │                Artist Player Lyrics Mine Local        │
│  │                Download Settings                      │
│  └─ styles/       CSS 变量（沿用现有 themes.js 取色算法） │
└─────────────────────────────────────────────────────────┘
```

**关键接口边界**（不管框架选哪个都必须成立）：

- `core/audio`: `play(url)` / `pause()` / `seek(s)` / `on('time'|'end'|'error')` —— 视图**永不**直接碰 `<audio>`（修问题 A）
- `stores/config`: 唯一持久化出口，diff 写盘 —— 修问题 B
- `data/repository`: 每个接口一个方法，瘦身下沉到这里而不是主进程 if 分支 —— 修问题 C
- `Norm.key = source:id` 保留为唯一身份键（约束 3）
